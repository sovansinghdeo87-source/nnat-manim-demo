# Pattern Completion → Color or Shading Continuation

150 items: 5 grades (K–4) × 5 base questions (one per progression theme)
× (1 original + 5 palette variations).

Unlike Repeating/Alternating Patterns (cyclic, wraps back around), this
subskill is a **monotonic progression** — each step continues a trend
by one more increment, never wraps. Five themes (`ATTRIBUTES` in
`_shared/pattern_lib.py`):

- `shade_darker` / `shade_lighter` — same shape/hue, fill opacity
  increases or decreases every step
- `hue_warm` — color walks along a pale-yellow → deep-maroon gradient
- `hue_cool` — color walks along a pale-cyan → deep-violet gradient
- `intensity_pink` — color walks along a pale-pink → deep-magenta gradient

Gradients are generated by linear RGB interpolation between two endpoint
hex colors (`_gradient()`), not hand-picked per step — easy to retune by
changing just the two endpoints.

Distractors: one-step-too-far (overshoot), the same step repeated
("didn't progress"), a shape swap (right color, wrong shape), and
either a far-away unrelated color (grades K–2) or a two-steps-too-far
overshoot (grades 3–4, harder near-miss).

## Regenerating

```bash
cd question_bank/pattern_completion/color_shading_continuation
python generate_bank.py
```

## Rendering

Pick any entry's `question_id` out of one of the files in `questions/`, then render it by
setting `QUESTION_ID` (same code every time -- only the parameters change):

```bash
cd <this subskill dir>
QUESTION_ID=<question_id> manim -s -qh question_image_scene.py QuestionImage
QUESTION_ID=<question_id> manim -pqh explanation_video_scene.py ExplanationVideo   # needs Azure creds
```

Omitting `QUESTION_ID` renders the first entry of the first file in `questions/` as a default.
