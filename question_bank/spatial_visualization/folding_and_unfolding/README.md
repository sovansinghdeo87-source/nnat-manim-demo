# Spatial Visualization → Folding and Unfolding

150 items: 5 grades (K–4) × 5 base questions (one per fold pattern) ×
(1 original + 5 palette variations).

The classic paper-folding puzzle: a square grid of paper is folded
along one or more lines, a hole is punched through the folded
(stacked) layers, and the paper is unfolded. The question shows the
grid with its fold line(s) marked (dashed) and a dot at the punch
location — the standard print-test convention — and the answer choices
show candidate unfolded hole patterns.

This is modeled **rigorously**, not just visually: each fold is a
reflection of grid coordinates (vertical: `c -> n-1-c`, horizontal:
`r -> n-1-r`, diagonal: `(r,c) -> (c,r)`). The actual unfolded hole set
is the closure of the punch point under the group generated by the
fold reflections used — exactly what happens physically. One fold
doubles the hole count (2 holes); two perpendicular folds quadruple it
via the Klein four-group `{identity, vertical, horizontal, both}` (4
holes).

- `fold_vertical` — 1 vertical fold, 4×4 grid → 2 holes (easiest)
- `fold_horizontal` — 1 horizontal fold, 4×4 grid → 2 holes
- `fold_both` — vertical + horizontal folds, 4×4 grid → 4 holes
- `fold_both_large` — vertical + horizontal folds, 6×6 grid → 4 holes
  (more position variety, harder)
- `fold_diagonal` — 1 diagonal fold → 2 holes (hardest — diagonal
  folds are intuitively harder to visualize than axis-aligned ones)

Distractors are the on-point mistakes: forgetting one of two folds (or
over-folding a single-fold question along an extra axis), folding
along the wrong axis entirely, punching the right spot under the wrong
fold vs. the right fold but a shifted punch spot, and an unrelated
punch location — plus a bounded diagonal-shift fallback so distractor
generation always terminates.

Validated programmatically across all 150 specs with real geometric
checks, not just uniqueness: punch cells are always in bounds, the
correct hole count exactly matches the fold count (2 for one fold, 4
for two), every hole is in bounds, and — critically — the correct
answer's hole set is verified **closed** under reflection across every
fold axis used (reflecting any hole back across any fold line lands on
another hole already in the set). Spot-rendered and visually confirmed
for both the hardest standard case (`fold_both`, grade 3: punch at
row 0, col 1 correctly unfolds to the expected 4-dot symmetric pattern)
and the diagonal case (`fold_diagonal`, grade 4: punch at (0,1)
correctly unfolds to the diagonal mirror pair `{(0,1), (1,0)}`).

**Known simplification**: fold lines are always through the exact grid
center (no off-center folds), consistent with the majority of
print-test paper-folding items; off-center folds would need a
non-square visible region after folding and were judged out of scope
for this auto-generated pass.


## Rendering

```bash
cd question_bank/spatial_visualization/folding_and_unfolding
QUESTION_ID=<question_id> manim -s -qh question_image_scene.py QuestionImage
QUESTION_ID=<question_id> manim -pqh explanation_video_scene.py ExplanationVideo   # needs Azure creds
```

Omitting `QUESTION_ID` renders the first entry of the first file in `questions/` as a default.
